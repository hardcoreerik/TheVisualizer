# Windows Desktop v0.1 Scope

## Outcome

v0.1 proves that a user can launch TheVisualizer on a supported Windows desktop, select system audio or a microphone, choose a visual, and run a stable audio-reactive presentation in a window or fullscreen.

It is a visualization player, not a media player or preset-authoring suite.

## Required behavior

### Audio sources

- Enumerate available Windows system-output loopback and microphone sources.
- Select and display the active source.
- Offer an automatic default-output choice and handle output changes without silently visualizing the wrong device.
- Display distinct states for silence, disconnected devices, capture errors, and unsupported configurations.
- Keep capture callbacks bounded and separate from rendering.

### Shared visual inputs

The host supplies visuals with:

- monotonic time and frame delta
- recent normalized waveform
- normalized spectrum
- RMS and peak energy
- low, mid, and high frequency-band energy

Exact sample rates, FFT sizes, smoothing, band boundaries, and buffer lengths are outputs of feasibility measurements rather than fixed planning assumptions.

### Player experience

- Windowed, borderless, and fullscreen modes
- Compact overlay for source, preset, presentation mode, and status
- Keyboard controls for showing the overlay, changing presets, entering or leaving fullscreen, and exiting safely
- Clear recovery when capture or rendering is unavailable
- No requirement for a media library, playlist, or file playback

### Bundled visuals

1. Oscilloscope with neon trails
2. Spectrum-driven particles
3. Feedback tunnel

All three use the same host-owned render and normalized feature path.

### Extensions

- Discover and load declarative WGSL presets.
- Reject invalid or incompatible presets without terminating the player.
- Discover a versioned native plugin package but keep unknown plugins disabled.
- Explain that approving a native plugin allows code to run with the user's privileges and does not sandbox it.
- Load one explicitly approved example native plugin using the host-owned rendering lifecycle.

## Acceptance criteria

- System audio from at least a browser and one local application drives all three bundled visuals.
- A selected microphone drives all three bundled visuals.
- Source changes and default-output changes produce either successful recovery or a clear actionable state.
- Silence does not produce unstable values, runaway motion, or repeated errors.
- Preset changes do not restart audio capture.
- Window resize and presentation-mode changes do not require restarting the application.
- An invalid shader preset is rejected while the player remains usable.
- An unknown native plugin does not execute before explicit approval.
- The example native plugin receives no direct GPU or native window handle.
- Targeted checks and a clean-package smoke test are recorded in [Project Truth](../PROJECT_TRUTH.md).

## Out of scope

- Audio or video file playback
- Playlists and media libraries
- Preset or shader editor
- Automatic preset rotation
- Marketplace, accounts, downloads, or updates
- Signed-plugin infrastructure
- Legacy Winamp visualization DLL loading
- MilkDrop/projectM compatibility
- macOS or Linux release packages
- MIDI, OSC, sensors, telemetry, or network input adapters
- Mobile or embedded delivery
